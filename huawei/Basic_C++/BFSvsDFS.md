### bfs vs dfs
- 两者本质上都是“遍历状态空间”，区别不在于题目名字，而在于“先往哪边搜”和“适合保留什么信息”。不要把 dfs 直接理解成“只管算路径条数”，也不要把 bfs 直接理解成“只管求最短路”。

- dfs 更像“沿着一条路先走到底，再回头改选别的路”。它更适合下面几类题：
    - 枚举所有方案、所有路径、所有选择分支。你在递归里不断 push / pop path，本质上就是回溯。
    - 在树上做自底向上的信息汇总。比如像 P13057、P14050 这类题，会把子树的信息递归返回给父节点，再在当前节点做合并。
    - 只需要判断可达性，或者统计连通块数量。像 P13061 这种用 dfs 统计连通分量，核心就是“没访问过就继续往深处走”。
    - 图上有回环时，dfs 常常要配合 parent 或 visited。树上题一般用 parent 就够了，因为只要避免回到父节点即可；一般图就要更稳妥地用 visited。

- bfs 更像“按层扩张”，先处理离起点近的状态，再处理更远的状态。它更适合下面几类题：
    - 无权图最短路、最少步数、最少操作次数。像 P13063 的迷宫最短步数，本质就是第一次到达某个点时，它的距离已经是最短的。
    - 多源最短路。像 P14047 这种从多个起点同时往外扩散，最终求所有点到最近起点的距离，或者“多个终点反推最近距离”，都是 bfs 的典型用法。
    - 线路图、换乘图这类“把原问题转成图之后再按层搜”的题。像 P4357、P4358 的关键点不是 bfs 本身，而是先把状态图建对，再用队列按层推进。

- 结合你做过的题，最实用的区别可以这样记：
    - 如果题目要的是“把所有可能性都试出来”，优先想 dfs。
    - 如果题目要的是“最短、最近、最少步数”，优先想 bfs。
    - 如果题目要的是“树上某个节点的子树信息”，优先想 dfs，因为 dfs 天然适合从子节点汇总到父节点。
    - 如果题目要的是“从一个点同步扩展到一圈点”，优先想 bfs，因为它天然就是一层一层推进。

- 写代码时的常见区别：
    - dfs 里最重要的是递归边界、回溯、以及如何避免走回头路。
    - bfs 里最重要的是队列、visited 或 distance 的初始化，以及“入队时标记”还是“出队时标记”。一般为了避免重复入队，最好在入队时就标记已访问。
    - bfs 求最短路时，第一次到达某个点通常就是最优答案，所以可以直接维护 distance；dfs 通常不能天然保证第一次到达就是最优。

- 你现在这套题里可以形成一个更具体的经验：
    - 迷宫可达性、迷宫最短路、最近距离这些题，优先 bfs。
    - 树的遍历、树上统计、子树属性合并、路径构造这些题，优先 dfs。
    - 线路图、换乘图这种“先建图再搜”的题，核心不在 bfs 或 dfs，而在“状态应该怎么抽象成点，边应该怎么定义”。一旦状态图建对了，bfs 常常更适合求最少换乘，dfs 更适合枚举方案。

- 一句话总结：
    - dfs 解决的是“把所有路都走一遍，顺便把信息带回来”。
    - bfs 解决的是“按距离从近到远扩展，顺便拿到最短答案”。
